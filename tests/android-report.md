# Android stabilization report

Implemented against the Android portion of `PLAN_AUDITORIA.md` on 2026-11-10.

## Changes

- **F01:** explicit playback intent and reconnect generations invalidate queued work on pause/stop, including pause after focus loss. Reconnect also requires retained audio focus. Soft stop retains the prepared player; hard stop invalidates pending playlist work and tears down the service. Stopped controls cannot be recreated by player notification callbacks.
- **F02/F03:** manual metadata preserves omitted fields, publishes title/artist immediately and transmits explicit null artwork. Received metadata has separate fields and still produces events with automatic publication disabled. Disabling automatic updates invalidates pending automatic image downloads through a separate policy generation; authorized manual downloads remain valid. A later reenable cannot resurrect the old automatic request.
- **F05/F12:** each image replacement has a new generation, including changes within a station, explicit clear and download failures. Latest failures clear to the app icon; old failures and successes cannot overwrite newer art. Catalog and resumption icons use cached `content://` URIs. The app icon appears while an image downloads. Shared image/URI caching avoids rewriting the same cached bitmap. Read grants cover current and late browser clients plus explicit SystemUI/Auto/Assistant packages; an unavailable optional package cannot abort publication. FileProvider remains nonexported and the browser remains exported. Failed catalog downloads release their pending marker and become eligible for a later browse retry after 30 seconds; failure does not trigger a self-refresh loop. Current-service files are retained; files from earlier sessions are only eligible for pruning after 24 hours.
- **F07:** playlists support query/fragment URLs, relative M3U/PLS entries resolved against the final response URL, content-type detection for extensionless text/playlist responses, HLS `.m3u` delegation, and cold resumption. Stream generations reject previous station resolutions. HTTP preparation probes response headers on a worker before choosing playlist resolution or native playback. A typed resolution carries the HLS MIME type even for extensionless URLs; initial preparation and retries use the same MediaItem construction. Signed M3U URLs retain query `=` characters, while PLS settings are interpreted only in PLS context. Playlist reading rejects input beyond 256 KB before converting bytes to text or splitting lines.
- **F08/F09:** `playing` follows service events. The bridge reads the actual foreground status. The previous "service started" flag could be outdated. Foreground/focus/delivery failures report state and errors. Exported-service commands require a process-private random capability; browser/MediaSession controls remain available to Android Auto. The exported broadcast receiver forwards only known transport commands and can control native playback without a live JavaScript proxy.
- **F10/F11:** invalid regex replacements are contained. Cause-chain inspection distinguishes temporary HTTP 408/429/5xx, DNS and timeout failures from 404/file/content/parser/certificate failures. Existing retry limit and error event payload are preserved.
- **F15/F16/F17:** detailed Android debug/info logging respects Titanium's existing `TiConfig.LOGD` switch; all native diagnostics pass through a shared sanitizer that removes complete URL/userinfo/query values and caps output at 1024 characters. Raw metadata and rule JSON traces were removed, exception diagnostics retain types, and public JavaScript error payloads remain unchanged; `play()` aliases `start()`. Voice search selects only catalog stations and exposes the corresponding session action.
- Added `AUDIO_BECOMING_NOISY` handling and Media3 network wake mode. Image/playlist/reconnect tasks use a small worker pool; image input is bounded at 8 MB and decoded near a maximum dimension of 1024 before separate Binder scaling to 512. Downloaded artwork compression/file writes run on the worker; embedded art and initial app icon handling can still execute on the main thread.

## Durable regression command

```sh
python3 tests/android_regressions.py
```

Requires a JDK with `javac`/`java`. The test extracts actual Java methods, supplies minimal Android substitutes, serves real local HTTP fixtures, and creates/deletes generated Java/classes in a temporary directory. It does not depend on the audit's temporary folder. Sixty checks pass, including a positive authorized reconnect, queued reconnect after pause/focus loss, manual/received metadata isolation, latest/obsolete image success/failure, HTTP error causes, relative PLS and HLS delegation.

Before implementation the original audit probe reproduced the metadata, playlist, regex and resume defects. The initial durable harness was also run against the original source and failed at relative M3U; after correction that same harness passed. Additional coverage was added alongside the image/error/access work. Review regressions were observed failing before correction for signed M3U URLs, initial/retry HLS MIME retention, pending manual artwork on disabling automatic metadata, and catalog failure/retry behavior. Local HTTP fixtures also validate suffixless HLS MIME detection; a counting input stream verifies the playlist cap before a giant line can be allocated. `git diff --check` passes for the edited Android sources and test.

The first Titanium Android source build with the updated dependencies succeeded during implementation. See the overall validation report for the final source refresh, build, lint and resolved dependencies.

## Remaining acceptance limits

The method tests do not emulate an actual MediaSession/foreground service, Binder permissions, focus policy or OEM behavior. Real Bluetooth, headphone removal, prolonged suspension, vehicle voice search/cold connection and Patrick's exact reader/URI remain device acceptance items. No device or automotive execution is certified here. The explicit URI reader list cannot predict every OEM package; clients that browse receive grants dynamically. Files from current service lifetime can grow during unusually long sessions because late-reader correctness takes precedence over aggressive deletion. Extensionless playlists served with an arbitrary binary MIME type still fall through to Media3. HTTP sniffing adds a request before native streaming; single-use URLs and servers restricting simultaneous connections need real endpoint acceptance. The image cache is bounded by entry count, and initial fallback/embedded-art processing still has main-thread work.

## API 36 queued hard-stop regression

A physical OPPO smoke run exposed `ForegroundServiceDidNotStartInTimeException` after immediate `hardStop(); setStream(relativePLS); start()`. The hard-stop path called unconditional `stopSelf()`: Android can already have registered later start IDs before delivering the earlier STOP intent, so that call can remove the service carrying queued SET_STREAM/PLAY and its foreground-start obligation. The service now records each delivered start ID and uses `stopSelfResult(lastStartId)`; it tears down when there is no newer start, while retaining the instance for already queued commands. Pending hard-stop dispatch is tracked separately from actual foreground state, so the bridge does not infer that an about-to-stop service remains ready. PLAY acknowledges foreground status before its already-playing or missing-configuration exits. Three new failing regressions were observed before the fix; positive/negative service-stop and foreground-dispatch cases now pass. The coordinating agent reruns the same real-device sequence against the refreshed module.

Pending hard-stop requests use a synchronized set of distinct per-intent markers. Successful completion and bridge/receiver delivery failures release only the matching marker, so a failed dispatch cannot leave foreground readiness disabled or clear another pending stop. The exact failed-dispatch path was observed red through the extracted bridge method and now passes; a separate case retains a newer marker while an older one finishes. The diagnostic sanitizer also has a before/after regression confirming signed URL, userinfo and local content-URI values cannot reach native diagnostic output.
